# Логи AdFox

Локальное приложение на Python. Скачивает почасовые логи, фильтрует их и сохраняет TSV. Интерфейс работает в браузере, обработка — на вашем компьютере.

## Запуск на macOS

Все файлы, необходимые для запуска и проверки приложения, находятся в папке `adfox_logs_app`. Нужен Python 3.11 или новее. Откройте `adfox_logs_app/start.command`. При первом запуске нужен интернет для установки библиотек. Если двойной щелчок не работает, в Терминале напишите `bash `, перетащите туда `start.command` и нажмите Enter. Окно терминала оставьте открытым. Остановка: Ctrl+C.

Вручную из папки приложения:

```sh
cd adfox_logs_app
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py --server.address 127.0.0.1
```

## Запуск на Windows

Нужен Python 3.11 или новее. Откройте папку `adfox_logs_app` и дважды щёлкните `start_windows.bat`. При первом запуске потребуется интернет: файл создаст виртуальное окружение и установит библиотеки. Оставьте открытым окно запуска. Чтобы остановить приложение, нажмите Ctrl+C в этом окне.

## Подключение и работа

Приложение использует существующие AWS-профили через boto3. В настройках можно указать профиль; пустое значение использует стандартный поиск доступа boto3. Ключи не записывайте в код или JSON настроек. Endpoint, bucket и папка перенесены из исходного скрипта. Proxy по умолчанию выключен. Может потребоваться рабочая сеть или VPN. Подключение к приватному S3 при разработке не проверялось.

Адрес S3 может содержать только `http`/`https`, hostname (в том числе `localhost`,
IPv4 или IPv6), необязательные порт и path. Если схема не указана, приложение
однозначно добавляет `https://`. Query и fragment не поддерживаются. Не помещайте
логин, пароль или другие учётные данные в URL: такой endpoint сразу сбрасывается к
стандартному адресу и не попадает в рабочее состояние или экспорт. Доступ задаётся
только через AWS-профиль или стандартную цепочку boto3.

1. Выберите скачивание или локальный `.tsv.gz` / `.tsv`.
2. Укажите дату и час: они используются в имени объекта без преобразования часового пояса.
3. Настройте поля и условия. Каждое значение вводите с новой строки, запятые остаются частью значения.
4. Для скачивания выберите, нужно ли оставить сырой архив после успешной фильтрации.
5. Укажите папку и имя результата, нажмите кнопку запуска.
6. Полный результат сохраняется на диск; интерфейс показывает первые 50 строк и счётчики.

Операция выполняется в фоновом потоке. Интерфейс отдельно показывает подготовку,
скачивание, фильтрацию, готовность или ошибку. При скачивании видны полученный и
общий объём, процент и текущая скорость; после скачивания остаётся средняя скорость.
В режиме локального файла во время фильтрации показаны только её состояние и счётчики
строк: сведений о скачивании нет, потому что сетевой шаг не выполняется. В S3-режиме
сводка о завершённом скачивании, 100% и средняя скорость остаются видимыми во время
фильтрации, в том числе для пустого объекта или объекта с неизвестным размером.

Во время скачивания доступна кнопка «Пауза». Текущая порция размером не более 8 МБ
сначала заканчивается, сетевой ответ закрывается, затем состояние меняется на «Пауза»
и кнопка становится «Продолжить». На паузе число байтов не растёт, сетевое соединение
не удерживается открытым, а текущая скорость явно равна 0 Б/с. Пока текущая порция
завершается, интерфейс показывает последнее измерение с подписью «Последняя измеренная
скорость». Только время фактической паузы исключается из средней скорости.
Продолжение начинается с первого недостающего байта новым S3 Range-запросом. Перед ним
приложение повторно проверяет размер, ETag и версию объекта; при изменении объекта
останавливается с ошибкой, не склеивая разные версии. Для этой безопасной схемы S3
должен разрешать HEAD и Range GET.

Кнопка «Отменить» сначала только открывает подтверждение. «Вернуться» закрывает его:
задание остаётся в прежнем состоянии, файлы не удаляются. После «Подтвердить отмену»
worker останавливается на границе порции скачивания или между строками фильтрации,
очищает принадлежащие заданию файлы и только затем показывает состояние «операция
отменена». Пауза доступна только при скачивании; отмена — также на паузе и во время
фильтрации. После обработки приложение на короткое время переходит в состояние
«финализация»: в этот момент кнопка отмены уже скрыта, а подготовленные файлы
атомарно публикуются. Запрос отмены, поступивший после начала финализации, не меняет
успешный результат на ложное состояние «отменено».

Пока операция идёт, кнопка запуска и поле папки результатов заблокированы. Текущая
задача сохраняется при автоматических перезапусках скрипта Streamlit в этой сессии,
а повторное нажатие не создаёт второй поток. Дополнительно архив и итоговый TSV
резервируются небольшими sidecar-файлами `.adfox.lock`: это защищает одинаковые пути
между разными вкладками и экземплярами приложения. После успеха, ошибки или отмены
операция удаляет только собственные lock-файлы.

Все фильтры соединяются через И. Внутри списка достаточно одного совпадения. Для отрицательных условий исключается каждое перечисленное значение. Регистр и пробелы учитываются. ID сравниваются как текст: `01` отличается от `1`. Для пустых значений есть отдельные условия.

По умолчанию: `banner_id = 208684` и `flag_virtual = 0`. Это логика исходного скрипта: переменная campaign_ids на самом деле фильтровала banner_id, колонку 11. Для кампаний выберите campaign_id.

Все 101 поле доступны в списке. В выпадающем списке показаны короткие подписи, а ссылка «Подробное описание полей» открывает общую таблицу с полными пояснениями ко всем полям. Поля `oc1`–`oc63` с одинаковым описанием объединены в таблице в одну строку. Неизвестные расшифровки помечены словом «уточняется»; тексты меняются в `adfox_logs_app/fields.py`. `adfox_logs_app/log_headers.tsv` содержит по одному имени на строку.

Колонки находятся по заголовку самого лога. Первая строка должна содержать уникальные названия полей. Кодировка UTF-8, разделитель — табуляция. Кавычки не имеют специального значения. Строки с количеством колонок, отличающимся от заголовка, пропускаются и учитываются в счётчике.

Флажок «Оставить сырой лог» относится только к архивам, скачанным приложением из S3. По умолчанию он включён. Если его выключить, новый `.tsv.gz` удаляется только после полностью успешной фильтрации и сохранения итогового TSV. При обычной ошибке полностью скачанный архив остаётся для диагностики или повторной обработки, а временный `.part` удаляется. При подтверждённой отмене удаляются только `.part`, новый сырой архив и незавершённый временный TSV, созданные текущим заданием. Архив и итоговый TSV, существовавшие до старта, а также посторонние `.part` не удаляются. Старый итоговый TSV заменяется только после успешной фильтрации. В режиме локального файла исходный `.tsv.gz` или `.tsv` никогда не изменяется и не удаляется независимо от значения настройки.

При скачивании из S3 полностью полученный архив остаётся собственным временным
`.part` до окончания фильтрации. Публикация итогового TSV, публикация архива (если
его нужно оставить) и решение удалить новый сырой архив выполняются в одной короткой
финализации. Поэтому отмена до этой границы сохраняет прежние итоговый TSV и архив
без изменений; после границы операция обязательно заканчивает начатый commit.

Для замены существующего файла нужен отдельный флажок разрешения перезаписи. Политика
повторно проверяется непосредственно при атомарной публикации архива и итогового TSV:
файл, появившийся уже после нажатия кнопки, без этого разрешения не заменяется. Если
другая операция уже заняла тот же архив или результат, новая операция завершается
понятной ошибкой и не трогает её файлы. Разные пути можно обрабатывать параллельно.

Рабочее состояние сохраняется автоматически после изменений и восстанавливается после полного перезапуска Streamlit. Сохраняются папка результатов, проверенный S3 endpoint без учётных данных, bucket, prefix, AWS-профиль, proxy, источник, настройка хранения сырого лога, путь локального файла, имя результата, дата, час и фильтры. Доступны даты начиная с 2020 года; будущие дата и час выбрать нельзя. Разрешение перезаписи из соображений безопасности не сохраняется и после нового запуска всегда выключено.

Файл состояния находится вне папки приложения:

- macOS: `~/Library/Application Support/AdFox Logs/state.json`;
- Windows: `%LOCALAPPDATA%\AdFox Logs\state.json`;
- Linux: `$XDG_CONFIG_HOME/adfox-logs/state.json` или `~/.config/adfox-logs/state.json`.

Запись выполняется через временный файл и атомарную замену. Повреждённый или созданный более новой версией приложения файл не мешает запуску: приложение показывает предупреждение и восстанавливает безопасные значения либо корректную часть данных. Если старый `state.json` или импортируемый JSON содержит userinfo в endpoint, адрес сбрасывается к стандартному без показа или повторного экспорта исходного URL.

«Сохранить настройки» по-прежнему выгружает отдельный JSON для ручного переноса. Для восстановления загрузите его в боковой панели и нажмите «Применить настройки». Если версия схемы новее поддерживаемой, приложение применит только известные корректные поля и после импорта один раз предупредит, что часть полей могла не восстановиться. Старый JSON без `schema_version`, даты, режима источника, `keep_raw` и внутренних идентификаторов фильтров поддерживается без такого предупреждения; для отсутствующего `keep_raw` безопасное значение по умолчанию — оставить архив. Некорректный JSON или некорректные типы в текущей и старой схеме отклоняются без изменения настроек. Любой фильтр можно удалить кнопкой в его строке; порядок и значения остальных строк сохраняются. Всегда остаётся не менее одного и не более 30 фильтров.

## Как поддерживать

- `adfox_logs_app/app.py` — интерфейс, отображение состояния и запуск фоновой операции.
- `adfox_logs_app/app_state.py` — проверка, восстановление и атомарное сохранение рабочего состояния; управление списком фильтров.
- `adfox_logs_app/operation_state.py` — потокобезопасная модель операции и защита от повторного запуска.
- `adfox_logs_app/execution.py` — фоновое выполнение без вызовов Streamlit.
- `adfox_logs_app/download.py` — S3 через boto3, HEAD и последовательные Range GET по 8 МБ; AWS CLI не требуется.
- `adfox_logs_app/operations.py` — порядок скачивания, фильтрации и безопасного удаления нового архива.
- `adfox_logs_app/path_ownership.py` — межсессионное резервирование итоговых путей и атомарная публикация с учётом разрешения замены.
- `adfox_logs_app/filtering.py` — построчная обработка, независимая от интерфейса.
- `adfox_logs_app/fields.py` — короткие подписи и полные описания полей.
- `adfox_logs_app/pages/1_Описание_полей.py` — отдельная страница справочника полей.
- `adfox_logs_app/tests/` — проверки логики и сохранности файлов при ошибках.

Начните изучение с `adfox_logs_app/filtering.py`: Rule описывает условие, filter_log обрабатывает строки. Большие файлы не загружаются целиком в память. Скорость на реальных объёмах не измерялась, Python может быть медленнее awk.

Фоновая задача привязана к сессии Streamlit и не переживает остановку процесса
приложения. Защита путей при этом общая для вкладок и процессов. После аварийного
завершения на диске может остаться `.adfox.lock`: на macOS/Linux lock умершего процесса
безопасно распознаётся и восстанавливается автоматически. Повреждённый lock, а на
Windows и любой сомнительный устаревший lock, не удаляется вслепую: сначала закройте
остальные экземпляры приложения, затем удалите указанный в сообщении sidecar вручную.
Не удаляйте lock работающей операции.

Проверки из папки `adfox_logs_app` (108 тестов успешно на Python 3.14.7 / macOS):

```sh
python -m unittest discover -s tests -v
```

Для обновления библиотек активируйте окружение и выполните:

```sh
python -m pip install --upgrade -r requirements.txt
python -m unittest discover -s tests -v
```

Перед обновлением сохраните рабочую копию приложения и JSON настроек. requirements.txt задаёт диапазоны версий. requirements-tested.txt фиксирует проверенное окружение Python 3.14 / macOS; его можно передать pip вместо requirements.txt для повторения версий. Windows-пути и `start_windows.bat` проверены чтением кода, но фактический запуск на Windows не выполнялся.

Тесты включают независимую проверку состояния, прогресса, скорости без времени паузы,
возобновления и отмены, управляемую имитацию S3 с Range без сетевого доступа, сохранность
старых файлов и сценарии подтверждения через Streamlit AppTest. AppTest не воспроизводит
периодический таймер браузера, поэтому завершение фоновой операции проверяется
контролируемыми повторными запусками; живое обновление индикатора следует дополнительно
смотреть в обычном браузере. Доступ к приватному S3 тестами не проверяется.
Тексты ошибок перед показом в интерфейсе маскируют распространённые формы ключей,
токенов, паролей и учётных данных в URL; секреты всё равно не следует вводить в поля
приложения или передавать в отчётах об ошибках.

## Для доработки с чат-ботом

Передайте чат-боту `AI_CONTEXT.md` и актуальные исходники приложения. В документе есть архитектура, правила фильтрации, ограничения и шаблон запроса. Ключи доступа, `.venv` и реальные логи передавать не нужно.
