# Этап 2: настройка хранения сырого лога

Продолжай работу над приложением «Логи AdFox» после полностью завершённого этапа 1.
Это локальное приложение Python + Streamlit, которое скачивает почасовой `.tsv.gz`
из S3 и фильтрует его в TSV либо фильтрует указанный локальный файл. До начала работ
полностью прочитай `README.md`, `AI_CONTEXT.md` и актуальный код. Проверь, что
находишься в ветке `codex/download-improvements`, этап 1 присутствует в её истории,
а рабочее дерево не содержит неожиданных изменений.

Сохраняй текущий дизайн, русские подписи, простую архитектуру и существующие правила
фильтрации. Не переставляй разделы и не делай визуальный редизайн.

## Что нужно сделать

1. Добавь в подходящем месте существующего интерфейса флажок «Оставить сырой лог».
2. Настройка должна участвовать в автоматическом сохранении состояния, созданном на
   этапе 1, а также в ручном импорте и экспорте настроек JSON. Старые JSON без этого
   поля должны продолжить работать с безопасным значением по умолчанию.
3. В режиме скачивания из S3:
   - при включённом флажке сохрани скачанный `.tsv.gz` после успешной фильтрации;
   - при выключенном флажке удали архив только после полностью успешной фильтрации и
     успешного сохранения итогового TSV;
   - при ошибке скачивания или фильтрации не удаляй полезный полностью скачанный
     архив молча: сохрани его для диагностики/повторной обработки и объясни это в UI;
   - временные `.part` по-прежнему должны очищаться после ошибки.
4. В режиме локального файла никогда не удаляй и не изменяй указанный пользователем
   исходный файл независимо от положения флажка. Подпись или недоступность элемента
   должна ясно показывать, что настройка относится только к файлам, скачанным этим
   приложением.
5. Не удаляй файл, который существовал до начала текущей операции. Сохрани текущую
   защиту от случайной перезаписи.
6. Раздели операции скачивания, фильтрации и очистки на небольшие тестируемые функции,
   если это нужно, но не усложняй проект фреймворками или базой данных.

## Что проверить

Добавь тесты как минимум для сценариев:

- включено «Оставить сырой лог» — архив остаётся;
- выключено — архив удаляется только после успешной фильтрации;
- ошибка фильтрации — скачанный архив не потерян, старый результат сохранён;
- локальный источник никогда не удаляется;
- ранее существовавший файл не удаляется;
- старый JSON настроек без нового поля корректно загружается;
- новое поле сохраняется и восстанавливается.

Не обращайся к реальному приватному S3 в unit-тестах: используй временные каталоги и
подмену скачивания. Запусти весь набор тестов. При изменении UI используй Streamlit
AppTest, если он доступен, и зафиксируй реальный результат. Обнови `README.md` и
`AI_CONTEXT.md`.
